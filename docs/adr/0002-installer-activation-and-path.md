# Installers activate a new binary only after it works, and ~/.local/bin wins

Setup scripts replace tools on machines that are in daily use, so a failed upgrade must leave the old tool working.

- **Stage, check, then activate.** `install_checked_binary` (`dot_local/private_lib/chezmoi/artifacts.sh`) copies the new binary into the destination directory, runs it, and only then replaces the old target. The uv, Claude Code, and mise setup scripts follow the same rule: keep the old link (including links into the old managed NVM tree) until the replacement starts, and remove only links that point into trees we manage.
- **Repo-managed copies come first in PATH during setup.** Non-interactive update wrappers can inherit Homebrew before `~/.local/bin`, and `add_to_path` only appends. The uv and Codex setup scripts therefore prepend their bin directory. To learn Homebrew's uv version, ask Homebrew's binary by path, because an older pinned copy in `~/.local/bin` comes first. When Homebrew's uv is newer, link it into `~/.local/bin`.
- **Check the managed link, not the first command on PATH.** Another copy (for example Omarchy's mise `claude@latest`) can hide a stale managed link. A broken launcher is repairable, so its exit status must not abort setup. npm can already use `~/.local` as its prefix: never create a self-link.
- **Upgrades need consent.** An older managed Claude Code copy is replaced only when the caller allows the npm download (`CHEZMOI_FORCE_UPDATE` or `TRUST_ON_FIRST_USE_INSTALLERS`). Trusted reviewed updates through `dotfiles-update` do not set force update. The npm install allows install scripts for `@anthropic-ai/claude-code` only, because its postinstall links the native binary.
- **Package-manager installs may lag the pin.** Homebrew casks can lag Tailscale's stable release, and we do not pin a macOS Tailscale app artifact. Treat the cask like other package-manager installs: warn, mark a lag state, and retry exact-version tracking on a later apply.
- **Pins are the steady state.** `REQUIRED_NVIM_VERSION` defaults to the repo pin, so `czuf` and `czm` converge each machine to the pins.
- **Global Node is for repo-managed agents.** `run_after_30-setup-mise` runs on every apply so global mise config changes install; projects override Node in their own `mise.toml`. Servers run it only when an optional JavaScript tool is enabled. On Debian/Ubuntu, mise comes from `extrepo` because it gives a signed repository definition.
- **Prerequisites stay cheap and tolerant.** Sudo is probed lazily so warm applies skip the probe. `jq` is essential because apply-time scripts (the Pi settings merge) need it. Interactive extras (delta, eza) are best effort, because package names vary by distro and the shell has fallbacks. `brew_install_formula` lets the caller choose a retry without `--quiet` to keep package-specific fallbacks.
- **Before-scripts load helpers from the selected source.** `run_onchange_before_*` scripts run before the home copy of the helper library updates, so `scripts/lib/load-helpers.sh` and the prefetch script load the helper from the chezmoi source directory.
- **The chezmoi installer can ignore `-b`.** `bootstrap-vps.sh` moves the binary from `~/.local/bin` when that happens.
